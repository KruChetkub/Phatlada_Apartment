# มาตรการความปลอดภัยและการรักษาความมั่นคงปลอดภัยทางเทคนิค (Data Security Measures)
**ระบบบริหารจัดการหอพักภัทร์ลดา อพาร์ตเมนต์ (Phatlada Apartment)**

**วันที่มีผลบังคับใช้:** 19 กันยายน 2569  
**เวอร์ชัน:** 1.0

---

## 1. วัตถุประสงค์
เอกสารนี้กำหนดมาตรฐานและมาตรการความมั่นคงปลอดภัยสารสนเทศ (Information Security Measures) ทั้งทางเทคนิคและการบริหารจัดการ สำหรับระบบภัทร์ลดา อพาร์ตเมนต์ เพื่อให้มั่นใจในความลับ (Confidentiality) ความถูกต้องสมบูรณ์ (Integrity) และสภาพพร้อมใช้งาน (Availability) ของข้อมูลส่วนบุคคลและข้อมูลระบบ

---

## 2. มาตรการทางเทคนิค (Technical Security Measures)

### 2.1 การเข้ารหัสข้อมูล (Encryption)
- **Data in Transit (ข้อมูลขณะรับส่ง):** ข้อมูลทุกรายการระหว่างเว็บเบราว์เซอร์กับเซิร์ฟเวอร์ถูกเข้ารหัสผ่านโปรโตคอล **HTTPS / TLS 1.3**
- **Data at Rest (ข้อมูลที่จัดเก็บในฐานข้อมูล):** ฐานข้อมูล Supabase PostgreSQL มีการเข้ารหัสพื้นที่จัดเก็บระดับดิสก์ (AES-256)
- **Client-side Storage Protection:** ข้อมูลที่จัดเก็บบนเบราว์เซอร์ถูกเข้ารหัสผ่านโมดูล `secureStorage` ป้องกันปัญหา Cleartext Storage ตามมาตรฐาน CodeQL

### 2.2 การควบคุมการเข้าถึงและการแยกสิทธิ์ (Access Control & Isolation)
- **Role-Based Access Control (RBAC):** กำหนดสิทธิ์ผู้ใช้งาน 3 ระดับชัดเจน:
  - `OWNER` (เจ้าของ): สิทธิ์เต็มในการบริหารจัดการ จัดการการเงิน ดูรายงาน
  - `MANAGER` (ผู้จัดการ): สิทธิ์บันทึกผู้เช่า จดมิเตอร์ ออกใบแจ้งหนี้
  - `STAFF` (ช่าง/เจ้าหน้าที่): สิทธิ์ดูและอัปเดตงานแจ้งซ่อม
- **Row Level Security (RLS):** ตารางฐานข้อมูลทั้ง 14 ตารางเปิดใช้งาน RLS บังคับแยกข้อมูลตาม `dormitory_id` เพื่อป้องกันการเข้าถึงข้อมูลข้ามหอพัก
- **Password Hashing:** รหัสผ่านของผู้ใช้ถูกเข้ารหัสด้วยฟังก์ชันแฮชทางเดียวที่ปลอดภัย (Bcrypt / Argon2) บน Supabase Auth

### 2.3 การป้องกันช่องโหว่ทางเว็บ (Web Vulnerability Protection)
- **SQL Injection Prevention:** ใช้งาน Supabase SDK ผ่าน Parameterized Query ป้องกัน SQL Injection 100%
- **Cross-Site Scripting (XSS) Prevention:** React 18 ทำการ Escape ข้อมูล Dynamic ใน DOM อัตโนมัติ และไม่มีการใช้งาน `dangerouslySetInnerHTML`
- **Least-Privilege CI/CD:** GitHub Actions ใช้สิทธิ์แบบจำกัด `permissions: contents: read`

## 3. มาตรการด้านการบริหารจัดการ (Administrative Security Measures)
1. **การตรวจสอบสิทธิ์ก่อนเข้าถึง:** บังคับให้ผู้ใช้งานต้องยืนยันตัวตนก่อนเข้าถึงหน้าจัดการข้อมูลผู้เช่าและข้อมูลการเงิน
2. **การสำรองข้อมูล (Backup):** ฐานข้อมูลบน Supabase มีระบบ Point-in-time Recovery และระบบส่งออกข้อมูล Backup สำรอง
3. **การทดสอบความปลอดภัยอัตโนมัติ (Automated Testing):** มีระบบรัน CI/CD และ CodeQL สแกนหาช่องโหว่ความปลอดภัยก่อนการ Deploy ทุกครั้ง

## 4. แผนรับมือเหตุการณ์ข้อมูลรั่วไหล (Data Breach Response Plan)
ในกรณีที่เกิดเหตุสงสัยว่ามีข้อมูลส่วนบุคคลรั่วไหล ทีมพัฒนาระบบและผู้ควบคุมข้อมูลจะดำเนินการ:
1. **ระงับเหตุทันที (Containment):** ตัดการเชื่อมต่อหรือระงับบัญชีที่ต้องสงสัยภายใน 1 ชั่วโมง
2. **ประเมินผลกระทบ (Risk Assessment):** ตรวจสอบขอบเขตของข้อมูลและผลกระทบต่อเจ้าของข้อมูล
3. **แจ้งเตือน (Notification):** หากมีความเสี่ยงสูง จะดำเนินการแจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส.) ภายใน **72 ชั่วโมง** และแจ้งเจ้าของข้อมูลที่ได้รับผลกระทบทราบพร้อมแนวทางป้องกัน
